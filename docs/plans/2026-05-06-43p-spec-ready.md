## Locked decisions for 43p (don't re-decide — full rationale in spec §"Locked decisions")

1. **Heavy PR gating.** Every PR runs full AOT publish + size budget + IL warning gate. Public repo → Actions free + unlimited minutes, no Windows multiplier.
2. **Tag is canonical version.** csproj has no `<Version>`. Workflow extracts from `${{ github.ref_name }}`, passes `/p:Version=X.Y.Z`. **Do not add `<Version>` to csproj** — single source of truth at release time.
3. **First release `v0.1.0`. Strict SemVer only.** Tag regex `v[0-9]+\.[0-9]+\.[0-9]+`. No pre-release suffixes.
4. **Size budget**: hard fail at `Stickies.exe > 18 MB`, hard fail at `publish/ > 30 MB`. Current baseline 15.89 MiB / 28.27 MiB → ~13% headroom on the exe.
5. **Release notes via `gh release create --generate-notes`.** Solo project, commit-to-main flow.
6. **`workflow_dispatch` on release.yml for testing.** Skips `gh release create` (gated on `if: github.event_name == 'push'`). Artifacts uploaded as Actions artifacts (7-day expiry) for manual download/inspection.
7. **MSI shape**: WiX v5 SDK, `Scope="perUser"`, installs to `%LOCALAPPDATA%\Programs\Stickies\`, single Start Menu shortcut, `MajorUpgrade` auto-replaces older versions, **never touches `%LOCALAPPDATA%\Stickies\`** (the SQLite DB lives there). MSIX is explicitly banned in CLAUDE.md — plain MSI only.
8. **IL warning gate strict in CI only.** Workflow passes `/p:TreatWarningsAsErrors=true /p:WarningsNotAsErrors=IL2104`. csproj stays loose for fast local iteration.

## Key invariants for implementation (don't violate)

1. **The tag is the version.** csproj has no `<Version>`. Don't add one "for clarity."
2. **`UpgradeCode` GUID never changes.** Generate once during plan/implementation, paste into `Product.wxs`, leave forever. If it rotates, users get duplicate Stickies entries in Add/Remove Programs.
3. **MSI never touches `%LOCALAPPDATA%\Stickies\`.** Owned by the app at runtime, not the installer.
4. **`workflow_dispatch` never publishes a Release.** `if: github.event_name == 'push'` guard on the create-release step is what keeps test runs from leaking junk releases.
5. **IL2104 is the only allowlisted IL warning.** New IL warnings → don't blanket-disable the gate; add to `WarningsNotAsErrors` in the workflow with a comment explaining why.
6. **CI runs the same publish flow as release.** The "main is shippable" guarantee depends on it. Don't short-circuit ci.yml to a faster path.
